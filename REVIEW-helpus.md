# Help-us security and privacy review

**Hold the anonymous send.** The running server receives the student's identity and their words together. Even an admin with only the ordinary app can identify the writer on a quiet day. The signed offer also reaches more people than the form discloses.

Reviewed `git diff origin/main...HEAD` at `16ea74fb` (merge base `e54682ff`). Line references are to the reviewed worktree.

## Critical

**C1. The owner can associate every anonymous submission with its author at receipt.** `server/kbtu/app.py:2291`, `web/src/lib/api/client.ts:74`, `server/kbtu/logic/helpus.py:51`. The Telegram request supplies signed identity with the plaintext body. The browser supplies its account cookie. The handler has both the resolved viewer and the text. Even after the request ends, the worker keeps a keyed hash of the day and account ID with the successful-send count. A single worker memory snapshot containing the key and counters can identify participating accounts against the account directory. On a day with one writer this identifies their text. The old counters survive midnight until the next valid anonymous send or process exit.

**Minimum safe release change.** Withhold this endpoint and its anonymous-send UI. To retain verified-student quotas, issue unlinkable single-use credentials to eligible students independently of sending. Redeem them without Telegram headers, account cookies or account activity updates. An owner who can observe the originating connection or change the submission client remains inside the trust boundary. Protection from that owner requires an independently trusted submission path that also conceals source and timing. Add the policy's warning about identifying details to the composer.

## High

**H1. The admin screens reveal when feedback arrives and who could have written it.** `server/kbtu/logic/helpus.py:86`, `server/kbtu/logic/helpus.py:94`, `server/kbtu/logic/daily.py:291`. The list exposes the current day, submission order, numeric IDs and new flags as soon as a row commits. The inbox count changes immediately. Admin's day view lists visitors by name, username and verified-student status. If the reader knows they did not send the note and there was only one other eligible visitor, the two screens identify the writer. Refreshing the list narrows the arrival window on busier days too.

The database has further timing evidence. Telegram requests can refresh the named `users.seen_at` and visit row. Browser requests can refresh the account-linked session time to the second. These commits precede the feedback insert in the same SQLite WAL. The first note also creates a row in the globally ordered bot outbox immediately. Adjacent timed queue entries can bracket its arrival even though delivery is scheduled for 09:00 the next morning. The strength of these correlations depends on traffic. `server/kbtu/app.py:272`, `server/kbtu/logic/web_auth.py:88`, `server/kbtu/db.py:78`, `server/kbtu/logic/helpus.py:57`, `server/kbtu/logic/seats.py:553`, `server/kbtu/schema.current.sql:124`.

**Minimal fix.** Expose only shuffled, closed batches in the list, badge and digest. Carry sparse batches into later release windows, suppress singletons, and omit original days and arrival IDs from the reader's data. Three notes can all come from one person. Generate the notification at batch release. For database-reader protection, mix submissions before they enter the application's database or WAL. Changing the display order alone leaves the original writes visible.

**H2. Every platform admin can read signed offers addressed to the creator.** `server/kbtu/logic/helpus.py:91`, `server/kbtu/logic/helpus.py:96`, `web/src/lib/i18n/en.ts:233`, `server/kbtu/i18n/legal/privacy.en.html:50`. A delegated admin receives every listed helper's profile, Telegram username, interests, note and exact submission time. The form names the creator as recipient, and the app explicitly supports appointing additional admins. The bot already selects founder-admins for its notifications. **Minimal fix.** Apply the existing owner predicate to the signed part of the list, its count and its read marker. Match the admin UI to that scope. Clarify the nearby promise that everyone is named in public credits, since public naming has its own opt-in. `server/kbtu/logic/oversight.py:222`, `web/src/lib/i18n/en.ts:222`, `server/kbtu/logic/credits.py:12`.

## Medium

**M1. The anonymous three-per-person cap fails under concurrent requests and in normal multi-worker deployment.** `server/kbtu/logic/helpus.py:46`, `server/kbtu/logic/helpus.py:60`, `Dockerfile:56`. Two simultaneous sends at a count of two can both pass before either increments it. SQLite serializes inserts, but the personal check is outside the transaction. Each worker has a separate allowance and each restart resets it. Almaty midnight also starts a fresh allowance within a rolling 24 hours. Early senders can consume the shared 200 slots, denying feedback to everyone else. The database enforces that global limit per calendar day. Its count scans retained feedback under the write lock because the schema has no day index. **Minimal fix.** Enforce the personal quota once, atomically, at anonymous credential issuance and consume each credential once across workers. A process lock fixes only the single-worker race. For the retained global limit, index the counted bucket or keep a bounded aggregate. `server/kbtu/migrations.py:2228`.

**M2. Both write endpoints pay for unbounded JSON before authorization or quota checks.** `server/kbtu/app.py:2291`, `server/kbtu/app.py:2295`, `server/kbtu/logic/helpus.py:67`. FastAPI buffers and parses a declared body before resolving the viewer. A rejected request can therefore consume worker memory and parsing time. The signed form also accepts arbitrarily many duplicate allowed kinds and walks them before checking the personal cap. The stored text limits constrain neither cost. **Minimal fix.** Reuse the byte-limited streaming reader and JSON error handling already used by public forms. Set a small wire limit that covers the allowed Unicode text and reject more than six kinds before iterating. `server/kbtu/app.py:66`, `server/kbtu/app.py:3089`.

**M3. Signed offers can flood the creator's Telegram and the shared delivery queue.** `server/kbtu/logic/helpus.py:70`, `server/kbtu/logic/helpus.py:75`, `server/kbtu/bot.py:960`. Each accepted offer creates an immediately due, distinct notification. Twenty verified accounts exercising their ordinary allowance can queue 60 messages to one recipient. The shared postman selects 50 due messages at a time. The anonymous route already coalesces notifications per day. **Minimal fix.** Coalesce offer notifications per creator and interval. Keep individual offers in the private list. Recheck the recipient's founder-admin status at delivery, since a queued template can outlive a role transfer. `server/kbtu/bot.py:346`.

**M4. An in-flight signed offer can survive completed account erasure.** `server/kbtu/logic/helpus.py:64`, `server/kbtu/logic/helpus.py:72`, `server/kbtu/logic/account.py:1382`, `server/kbtu/logic/account.py:1436`. The request checks a previously resolved student flag. If the deletion transaction commits before the offer obtains the write lock, deletion removes the student and existing offers but preserves the users row. The new offer's foreign key still succeeds, leaving its note and account ID after erasure. **Minimal fix.** Recheck current verified membership inside the offer's write transaction before insertion, or enforce an equivalent student foreign key with deletion semantics.

**M5. Spam can push genuine messages out of the admin's only readable page.** `server/kbtu/logic/helpus.py:95`, `server/kbtu/logic/helpus.py:100`, `server/kbtu/logic/helpus.py:107`, `web/src/screens/admin/AdminVoices.svelte:22`. The list shows the newest 300 of each kind, with no older page. Two days of allowed anonymous traffic can exceed that limit. Opening the sheet acknowledges every row, including older unread items and a submission that lands after the list response. **Minimal fix.** Page through unread released items and acknowledge only the items or closed batches actually returned to the authorized reader.

## Low

**L1. Reused IDs suppress notifications for new offers.** `server/kbtu/migrations.py:2234`, `server/kbtu/logic/helpus.py:75`, `server/kbtu/logic/helpus.py:86`. Deleting the newest helper's account can free the highest offer ID. Its successor can inherit both an already-read ID and an existing founder outbox key. The fresh offer then has neither a new badge nor a push. Expiry can similarly reset anonymous IDs when that table empties. **Minimal fix.** Use non-reusable internal IDs anywhere a read marker or deduplication key outlives its row. The repository already has `core.next_id`. Keep internal sequence numbers out of anonymous responses. `server/kbtu/logic/core.py:137`.

**L2. Expiry depends on a narrow nightly window and stale rows remain readable.** `server/kbtu/logic/helpus.py:112`, `server/kbtu/logic/daily.py:222`, `server/kbtu/logic/helpus.py:95`. The anonymous comparison retains day 90 and first deletes on day 91. Signed offers remain readable between their 180-day deadline and the next sweep. If the bot misses 00:00–03:00 Almaty, even a daytime restart leaves expired rows visible. Founder outbox references also survive the feature sweep, preserving submission-day or offer-event metadata beyond the text's lifetime. **Minimal fix.** Apply expiration cutoffs on reads and unread counts, prune overdue records at startup or the next available daily run, and expire obsolete notification keys. For anonymous records use a conservative day cutoff that meets the stated ceiling without storing a minute.

**L3. Telegram admin responses lack the cache protection used for contact details elsewhere.** `server/kbtu/app.py:2299`, `server/kbtu/app.py:309`. Browser-cookie sessions get `private, no-store`. The Telegram-authenticated list can enter a private HTTP cache, leaving helper contacts and notes on a shared device after the sheet closes or the role changes. This is a storage exposure. Source review found no ordinary non-admin API response containing the list. **Minimal fix.** Set `Cache-Control: private, no-store` on this response for both authentication modes, as the existing handle endpoint does. `server/kbtu/app.py:1165`.

**L4. The help ask adds synchronous storage work to every launch.** `web/src/App.svelte:490`, `web/src/lib/helpus.ts:24`, `web/src/screens/profile/Me.svelte:88`. App initialization reads, parses and rewrites the visit history before first paint, even on same-day reopens and after the prompt is permanently dismissed. Profile reads storage again before its deferred content. **Minimal fix.** Do the engagement bookkeeping in the existing deferred Profile work or after first paint, ahead of deciding whether to show the card. Skip writes when today's visit is already present or the prompt is finished. The new sheets also pass fresh loader functions into an identity-keyed cache on every tap. Stable loader references recover its same-frame repeat-open path and avoid accumulating cache entries. `web/src/App.svelte:55`, `web/src/App.svelte:250`.

## Logs, client storage and verification

- The production image disables Uvicorn access logs. The direct server command documented in the application enables Uvicorn's default access log, which records client address, method, path and status. An anonymous-send path with a 204 identifies a successful submission from that connection. At low volume its position can identify the corresponding text. Production ingress, CDN, tracing and log-retention settings are outside this worktree and remain unverified. Suppress identifying request metadata at every hop, including failed requests, and verify with synthetic traffic before enabling the channel. A first fetch of the feedback-specific lazy asset also signals that a client opened the form. `Dockerfile:56`, `server/kbtu/app.py:4`, `server/kbtu/app.py:792`, `web/src/App.svelte:251`.
- The inspected handler writes no author foreign key or submission audit event. Expected validation errors omit the input. Raw 429 responses distinguish the caller's personal limit from the global limit. This reveals quota state to that caller. There is no target-account parameter. The UI displays the same limit message for both. `server/kbtu/schema.current.sql:17`, `server/kbtu/app.py:558`, `server/kbtu/app.py:566`, `server/kbtu/logic/helpus.py:52`, `web/src/screens/profile/FeedbackSheet.svelte:24`.
- Feedback, offer notes and names render as Svelte text. The offer contact action uses the Telegram username from the account. The signed Telegram button uses a fixed translated draft. It does not include the anonymous textarea. The bot sends fixed templates. The app's persistent prompt keys record visit days and whether the ask was seen or tapped. Neither a submission flag nor the typed text appeared in that storage or the app's recovery snapshot. `web/src/screens/admin/AdminVoices.svelte:24`, `web/src/screens/admin/AdminVoices.svelte:37`, `web/src/screens/admin/AdminVoices.svelte:46`, `web/src/screens/profile/FeedbackSheet.svelte:40`, `web/src/lib/helpus.ts:6`, `web/src/App.svelte:744`, `server/kbtu/bot.py:346`.
- Ordinary account deletion includes the signed offer. The anonymous row survives account deletion by design. Nightly database backups have their own documented retention and account-deletion replay. The named tests exercise serial caps, a delayed template, basic authorization and sequential erasure. They do not establish operator anonymity or cover concurrent erasure. `server/kbtu/logic/account.py:1275`, `server/kbtu/app.py:501`, `server/kbtu/i18n/legal/privacy.en.html:87`, `server/tests/test_helpus.py:23`.
